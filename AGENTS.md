## Project snapshot

- What it is: Rebuild of the CAILab lab site (today a Google Site at cailab.info) as a static Jekyll site that Kenny deploys by hand to the lab's GitHub Pages and that AI harnesses can update cheaply.
- Language / runtime: Ruby 3.1.6 (`.ruby-version`, rbenv), Jekyll 3.10 via the `github-pages` gem. Not Homebrew Ruby 4.x: `github-pages` pins a liquid that breaks there. The shell must resolve `ruby` to 3.1.6 (rbenv shims first on PATH); `bin/check` fails loudly if not.
- How to run: `bundle exec jekyll serve --livereload` → http://localhost:4000. First time: `bundle config set --local path vendor/bundle && bundle install`.
- How to test: `bin/check` (strict Jekyll build, Minitest in `tests/`, bun unit tests, then browser E2E). The E2E is Playwright (`@playwright/test`, pinned in `package.json`, `bun.lock` committed; specs in `e2e/`, config `playwright.config.js`), run alone with `bin/e2e [spec]`: it builds the site into `.e2e-site` and serves it on port 4010 (never 4000, where the dev server runs) and blocks Google Fonts so measured heights use fixed fallback fonts. The pinned version wants Chromium revision 1234; `bin/e2e` never downloads a browser, so if it is missing run `bunx playwright install chromium`. Measured limits in `e2e/` sit just above the current numbers (comments give the before and after); change them deliberately, not to make a run pass.
- Lint / typecheck: none beyond the strict build in `bin/check`. Prettier can't parse Liquid, and no Ruby linter is added (dependency rule). The Python/JS gate table in `dev/AGENTS.md` doesn't cover this stack.
- Architecture: all content lives in `_data/*.yml` (lab, nav, news, people, publications, publication_types, research, funding, media, join, gallery), looped over by seven pages (`funding.yml` is kept but deliberately not rendered; `ResearchPageTest` guards that) through `_includes/` components. Tokens and components are in `assets/css/site.css` and documented on `/design-language/` (a hand-maintained page). `assets/js/rings.js` draws the name-seeded ring graphs and `assets/js/field.js` runs the hero canvas, with `_includes/field-static.html` as the no-JS fallback. `research.yml` holds the Human-Centred AI intro and three areas (`slug`, `title`, `short`, `pastel`, `summary`, `papers`, `more`; a paper may sit in several areas; seven areas at most, one pastel each); it alone feeds the Research page, the home tiles and the Join Us topics. `papers` are full papers shown as `paper-card`s (each needs a figure), `more` are other papers shown as links, both to `/publications/#pub-<id>`; Media renders on `/news/`. A publication may carry `figure:` and `video:` (a thumbnail and a click-to-load YouTube player sharing one dialog, `assets/js/figure.js`); `bin/figure` makes the images. `/publications/` folds each year into a native `<details class="year">`, newest year open and the rest closed; links into a closed year (`/research/` and Join Us deep-link to `#pub-<id>`) only work because `assets/js/year-folds.js` opens the folds around the target and re-scrolls (it also reveals Expand all). The same script runs the filter bar: one row of search plus Type and Research area menus of chips, with Expand all in the same row (below 640px the menus, Clear and Expand all sit behind one Filters button, and the recruitment banner shrinks to one row; publication rows become compact cards with the thumbnail beside the title, each area's Research cards a swipeable strip, the page header shrinks, a year's type counts become dots and numbers (names kept for screen readers) and the "More in this area" links run the venue into the title, all under 640px; area comes from `research.yml`, none means "Other"), mirrored to `?type=&area=&q=` and cleared first when a link targets a hidden row. It has its own bun test, `tests/year-folds.test.js`, which `bin/check` runs next to `tests/nav.test.js`. The Gallery (`gallery.html`, `_data/gallery.yml`, `_includes/gallery-album.html`) lists albums of lab photos by event under year headings, with a justified CSS grid (albums over 12 photos show 8 and fold the rest) and category chips (`assets/js/gallery-filter.js`, shown only when two or more categories are in use; its pure part is tested in `tests/gallery-filter.test.js`). Photos open in the same `figure-dialog` as Publications (`_includes/figure-dialog.html`), grouped per album: `assets/js/figure.js` adds steps, arrow keys, swipe and a counter. `gallery_specimen.yml` (publication figures) feeds the specimen album on `/design-language/`, which the layout and lightbox tests also run on. `GalleryVisibilityTest` ties the page, its nav entry (just before Code) and a non-empty `albums` list together, so an empty list means unpublish (`published: false`, no nav entry); `bin/figure photo` makes the images.
- Entrypoints / important files: `_config.yml`, `_data/`, `_layouts/default.html`, `_includes/`, the pages (`index.html`, `research.html`, `news.html`, `people.html`, `publications.html`, `join-us.html`, `design-language.html`), `assets/`, `bin/check`, `tests/site_test.rb`.
- Constraints / what to watch:
  - `exclude:` in `_config.yml` replaces Jekyll's defaults, so `Gemfile`, `Gemfile.lock` and the like must stay listed, and `theme: null` stops the gem publishing its own `assets/css/style.css`; `PublishedFilesTest` enforces both.
  - The old Google Site's `/home`, `/media` and `/funding` are redirect stubs (`home.html`, `media.html`, `funding.html`, via `jekyll-redirect-from`): meta-refresh pages, not server 301s. `/funding` goes to `/research/` because the Funding section is hidden. `OldUrlRedirectsTest` guards them.
  - `CNAME` (the production host) and `url:` in `_config.yml` must agree; `ProductionIdentityTest` guards both plus the canonical and Open Graph tags. `favicon.ico` and `assets/img/apple-touch-icon.png` are cut from the logo's sphere on white (a missing favicon logs a 404 on every first visit).
  - Pages builds with its own gem versions and runs no custom Ruby plugins. The local build says "will this obviously break", not byte-for-byte truth. Anything generated (field hero, name-seeded ring graphs) must be client-side JS with a no-JS fallback.
  - The only address in the HTML is the contact `mailto:` (Kenny's choice, in `_data/lab.yml`); it is never visible text and no other address may appear. Tested.
  - Photos only for the director (`lab.yml`'s `director_photo`, rendered by its own card) and for people with a `photo:` in `people.yml`; Kenny confirmed consent for the old-site set on 2026-11-18, and any other person needs theirs first. A photo already here stays with the person when a member becomes an alumnus or a collaborator becomes a former collaborator (Kenny, 2026-11-20) and comes off on request; code can't check consent, so this rule is the check. Alumni and former collaborators render as `person-row` (28px, the original file scaled down, else a name-seeded ring) inside a closed `.fold`; the "Former collaborators" fold appears only once `collaborators_former` exists in `people.yml` (see the comment at its top for how to move someone). Images are metadata-stripped JPEGs in `assets/img`; `StrayFilesTest` allows only the declared ones.
  - Gallery photos are added only inside an album that carries `consent:` (the date Kenny confirmed web use for everyone identifiable in the photos and named in the captions; `GalleryRules` refuses an album without it), and a photo comes off on request. No full-resolution photos: images are made by `bin/figure photo` (upright, sRGB, no EXIF or GPS) at most 1280px on the long edge and 350 KB, thumbnails within 640x480 and 120 KB, and `GalleryRules` enforces those limits. They sit in `assets/img/gallery/<album>/<NN>.jpg` plus `<NN>-thumb.jpg`, one folder per album (the rest of `assets/img` stays flat); `StrayFilesTest` and `ImageMetadataTest` recurse, so an unlisted or metadata-carrying photo anywhere under `assets/img` fails. The first album (2 July 2026 day out) includes a group selfie in a Monopoly Hidden Singapore branded frame and background bystanders, both kept by Kenny's decision (2026-11-20).
  - Paper figures and videos are optional per publication, never a placeholder. Images are flat in `assets/img` as `pub-<slug>*.jpg`, made with `bin/figure` (it strips the metadata `sips` writes); `PublicationFigureTest`, `PublicationVideoTest`, `ImageMetadataTest` and `StrayFilesTest` guard them. No figure shows an identifiable participant or verbatim participant content unless Kenny confirms the consent covers web use; Kenny confirmed reuse rights for the set added on 2026-11-18. Video files never go in the repo: a YouTube ID only, and nothing loads until play is pressed.
  - News, people and the Join Us role sections and values were copied from the old site as written. The Join Us "How to apply" block (`join.yml` `apply:`) is Kenny's wording of 2026-11-20 and is the lab's intake filter: a package per role, a paper response, an AI note and a subject-line format, guarded by `JoinApplyTest`. Its `mailto:` button must never prefill a subject (tested), and the paper choices are `apply.paper.choices` (publication ids), limited to the CHI Honourable Mention and CSCW papers (tested against each paper's venue). The mission (`lab.yml`), the research intro and areas (`research.yml`) and the Join Us topic list are Kenny's own wording under the Human-Centred AI framing, rewritten 2026-11-18; `ResearchPageTest` blocks the retired "Society-Centred" umbrella from the framing data (past talk titles in `news.yml` stay). Unpublished work, such as the Small Language Model / mental-health line, joins an area only once it is public. News `text` and research/join bodies are Markdown. One news item has no date: it stays off the home preview but is listed on `/news/`.
  - The site is public: nothing under review or unpublished goes on it. `publications.yml` is hand-copied from the CV's `publications.bib` (never its `inreview` entries); `PublicContentTest` blocks any entry with no venue, date or public link, and any text reading as under submission.
  - Each publication carries `date` (earliest public availability: Crossref issued date, ACL Anthology month, or arXiv v1 month; `YYYY`, `YYYY-MM` or `YYYY-MM-DD`). `year` is the page's grouping key and must equal it. The list is kept newest first (a month-only date sorts after dated entries of that month); `PublicContentTest` and `PublicationsPageTest` guard this.
  - Each publication carries `type` (one of `publication_types.yml`), copied from the keywords of `personal/cv/publications.bib`, never chosen here; `PublicationFiltersTest` compares it by title when that repo sits beside this one and skips with a message when it doesn't. `publication_types.yml` also gives each type its colour (`tone`: spectrum 1-6, or 0 for grey; none shared) and `research.yml` gives each area a `short` name and a `pastel` (1-7, its own palette in `site.css` and on `/design-language/`, separate from the spectrum so a type colour never collides with an area colour; the page's hex values are tested against the CSS). Every paper ends with a label strip (`_includes/pub-labels.html`, on publication rows and Research cards): its type pill, then one tinted pill per area it sits in, none for "Other". The bib's `selected` keyword is deliberately not used on the site (a "Selected" chip was dropped, 2026-11-20); a test keeps the flag out.
- External services / secrets needed: none locally.
- Deploy target: GitHub Pages from `main` of `Context-Aware-Interaction-Lab/Context-Aware-Interaction-Lab.github.io`, served at https://www.cailab.info (the `CNAME` file; DNS is managed outside this repo). Manual deploy; never push to `main` without Kenny's go-ahead after he has inspected the local render.
- Current status + next steps: Live, Gallery included (one album). Done-gate exemptions taken: `rings.js` and `field.js` have no automated tests, and `figure.js` is tested for the figure dialog and the album lightbox (E2E) but not the video player; the Gallery chips' DOM wiring (only `gallery-filter.js`'s pure part is unit tested) has never run on a real page, since one category means no chips yet; `bin/figure photo` has no automated test (checked by hand on a synthetic rotated JPEG and on the first album's photos; a real HEIC is unsupported and unverified); and no alumnus or former collaborator carries a photo yet, so the `people.html` → `person-row` photo pass-through is untested on `/people/` until someone moves (the `/design-language/` specimen tests the include's photo branch).
